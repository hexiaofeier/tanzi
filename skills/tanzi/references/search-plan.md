# 搜查令：搜索设计

本参考将作者独立`sou-cha-ling`(搜查令Skill)的搜索设计方法整理为探子随包内容。它帮助确定“查什么、怎样搜、带回哪些字段”，不执行检索，不评价材料可信度，也不生成研究结论。无需安装其他 Skill。

## 何时使用

- 已有用户给出的关键词、搜查令或其他搜索计划：直接沿用，仅补缺失的平台、时间、字段等执行信息；不重复生成一份计划，不擅自扩展对象或渠道。
- 只有主题或研究问题：按本参考形成简短计划后继续采集，不强制等待用户批准。只有范围歧义会显著改变结果时，才确认一个关键问题。
- 范围明确的小任务：用几句话列明对象、查询和边界即可，不必填满所有表格。复杂任务首轮通常 2–5 组查询；仅在覆盖不足时追加，不把每个研究方向都机械搜索一遍。

本参考是探子的内部步骤，不是另一个需要用户调用的技能入口。纯关键词设计请求不因此改变探子的触发范围；外部搜索计划也不要求由“搜查令”生成。

## 1. 先定边界与主模式

明确研究问题、主对象、包含与排除、地域、时间窗、语言、指定平台、候选条数或其他采集上限。用户没有限定的项目可说明合理假设，不把示例平台当成必搜名单。

选择一种主模式，确有需要再组合：

| 模式 | 重点寻找 | 需设计的相反方向 |
|---|---|---|
| 行业与企业研究 | 定义、市场数据、产品、客户、订单、经营、政策、技术与竞争变化 | 退出、流失、落标、亏损、失效、替代，以及与增长叙述不一致的材料 |
| 用户研究 | 使用任务、潜在需求、购买与使用经历、付费、续费、投诉、职业社群讨论 | 非用户、不采用、弃用、退订、自建、延后购买，以及不围绕产品名表达的需求 |
| 舆情热点 | 起点事件、时间线、当事人回应、观点阵营、传播节点、跨平台变化与实际后果 | 质疑、澄清、更正、反转、完整上下文，以及热度之外的不同声音 |

行业与企业研究再区分视角：行业以品类、技术、场景或细分市场为主对象；企业以法律主体、品牌、产品或业务分部为主对象。

## 2. 建立对象池，控制扩展

先补齐主对象的中文名、英文名、简称、旧称、拼写变体；涉及公司时补法律全称、品牌、产品、子公司或证券代码，防止同名混淆。英文只在相关对象或来源确有需要时加入。

| 对象层 | 何时扩展 | 返回时的标签 |
|---|---|---|
| 主对象 | 用户明确指定的公司、产品、行业或事件 | 主对象 |
| 同类或替代 | 查选择、迁移或竞争关系时 | 同类／替代 |
| 通用品类或技术 | 产品名命中不足、需要寻找更广泛需求时 | 通用品类／技术 |
| 相邻使用场景 | 用户主要围绕任务表达需求时 | 相邻场景 |

只扩展与问题有关且未被用户排除的层，保留主对象的采集任务；不能用通用品类的材料冒充指定产品的使用情况。每条扩展材料保留对象层和原始对象名称。

## 3. 构造可执行查询

每组先组合“对象词＋一类问题词”，再按需增加材料词、地域、时间或排除词。不要把所有维度塞进同一个搜索框，也不要把分析框架里的抽象术语逐项变成必搜词。

| 构件 | 可选词举例 |
|---|---|
| 材料 | 年报、招股书、统计、政策原文、采购意向、中标、合同、访谈、实测、投诉、Issue、Discussion |
| 数据与经营 | 收入、销量、订单、客户数、价格、预算、回款、续费、装机、渗透率 |
| 用户任务与体验 | 怎么做、工作流、有没有、求推荐、麻烦、踩坑、付费、退订、迁移、不需要 |
| 事件与变化 | 融资、发布、升级、下线、回应、整改、并购、退出 |
| 反例与替代 | 不适合、失败、弃用、无效、没采用、平替、自建、取消订阅；必要时补 failed、alternative、cancel subscription 等表达 |
| 限定与排除 | 年份、季度、地域、产品型号、法律全称、同名无关对象；排除项须有明确理由 |

支持、失败、负面和未采用方向分成不同查询，不为了预设结论排除相反材料。用户指定时间窗时使用平台可用的时间筛选，并核对返回条目的发布时间；把年份写进搜索词不等于完成时间过滤。

搜索运算符仅在当前工具支持时使用：`site:`、`filetype:` 可用于支持它们的通用搜索引擎，不能原样塞入不支持这些运算符的平台站内搜索。

### 行业与企业研究：按题选词

以下是关键词方向，不是额外 Skill 的安装清单。只挑本轮相关行，不把 14 个方向全部执行。

| 方向 | 关键词组件 | 重点请求的原始字段 |
|---|---|---|
| 市场规模 | 定义、市场规模、收入、销量、价格、客户数、渗透率、预测 | 对象、地域、期间、单位、原值、分母、统计或预测方法 |
| 产业链 | 上下游、供应商、客户、渠道、产能、交期、认证、替代供应 | 环节、主体、关系、金额或占比、产能、责任与替代路径 |
| 商业模式 | 付款者、定价、计费单位、订阅、项目制、佣金、毛利、账期 | 谁付款、怎么收费、收入确认、交付成本、回款 |
| 竞争格局 | 玩家、竞品、份额、价格、中标、落标、进入、退出、并购 | 同一竞争范围内的对象、产品、客户、时间、份额口径与动作 |
| 宏观环境 | 收入、就业、利率、融资、人口、预算、资本开支、成本 | 指标定义、地域、频率、统计期、公布期和影响对象 |
| 政策监管 | 文号、征求意见、生效、许可、补贴、采购、处罚、废止 | 发文机关、法域、文件状态、发布日期、生效日、适用对象与执行记录 |
| 趋势变化 | 发布、融资、采购、订单、收入、续费、降价、退出、整合 | 发生期、披露期、信号类型、持续性、相反变化 |
| 驱动力 | 增长原因、量价、供需、技术成本、预算变化、约束、时滞 | 目标结果、候选原因、作用对象、时间关系、替代解释 |
| 行业痛点 | 等待、返工、停机、投诉、损失、放弃、人工处理、自建 | 承担者、场景、任务、损失、当前应对、失败或未发生案例 |
| 公司画像 | 法律全称、品牌、产品、管理层、官网、客户、订单、融资 | 主体对应关系、业务分部、产品、客户、原始披露和时间 |
| 财务 | 财报、附注、分部收入、现金流、应收、库存、负债、减值 | 报表主体、期间、币种、会计口径、原值、基期与调整项 |
| 治理与资本配置 | 控制人、投票权、董事会、激励、关联交易、融资、回购、分红 | 权利主体、决策事项、金额、时间、资金来源和用途 |
| 估值材料 | 市值、股本、净债务、可比公司、交易倍数、盈利预测 | 估值日、币种、指标口径、预测期、原始假设 |
| 投资假设材料 | 催化剂、预期、成立条件、风险、下行情景、历史失败、退出条件 | 假设原文、时间窗、观察指标、反例和条件；不在此生成投资建议 |

融资、发布、合作、中标、部署、验收、收入和续费是不同事件，要求分别带回，不能混成“成功案例”。

### 用户研究：按题选词

同时考虑使用者、采购者、付款者、潜在用户与退出者。按本题选择相关方向；查询既可围绕产品，也可围绕人群、任务和未满足的需求，不要求用户先说出产品名。

| 方向 | 关键词组件 | 重点请求的原始字段 |
|---|---|---|
| 任务与场景 | 怎么做、日常、工作流、步骤、麻烦、手动处理 | 人群、情境、任务、当前做法、困难原话 |
| 潜在需求 | 希望有、有没有、求推荐、想要、如果能、为什么没有 | 期望结果、触发情境、限制、现有替代方式 |
| 兴趣与讨论 | 值得、为什么火、好奇、机会、是否需要 | 关注主题、观点及理由、讨论时间、平台；区分好奇与实际使用 |
| 态度与情绪 | 喜欢、反感、担心、焦虑、看好、抵制、观望 | 原话、情绪对象、理由、转折、相反表达 |
| 产品体验 | 推荐、好评、差评、投诉、故障、退货、售后 | 产品与版本、场景、实际行为、问题、处理结果；区分亲历与转述 |
| 价格与选择 | 价格、预算、性价比、平替、续费、退订、不买 | 原始价格或预算及单位、付款者、选择、替代、购买状态 |
| 行为路径 | 试用、购买、实测、复购、一直用、流失、弃用 | 行为阶段、发生时间、频率、持续或退出原因、转用方案 |
| 职业人群 | 职业名、社区、经验、闲聊、吐槽、工作流 | 公开身份及其依据、工作任务、观点原话、上下文；身份未知则标未确认 |
| B 端角色 | 采购需求、预算、RFI、RFP、招标、部署、验收、续约 | 发起／审批／采购／付款／使用／实施角色、流程、预算、合同与验收状态 |
| 非消费与不采用 | 不需要、没兴趣、太麻烦、不值得、延后、自建、放弃 | 不采用原话、原因、替代做法、采用条件、样本边界 |

不把抱怨直接算作弃用、兴趣算作购买、采购者说法算作使用者体验。“沉默用户”只能寻找公开表达的不讨论、不采用或退出线索，不能根据没搜到帖子推断人群需求。原帖与评论保留各自身份依据、行为阶段和上下文，不把少量社群样本推成总体比例。

### 舆情热点：按题选词

关注发生了什么、谁在说、如何传播与变化，按本题选择相关方向；不在搜索设计阶段预判哪一方正确，也不预设必然存在反转。

| 方向 | 关键词组件 | 重点请求的原始字段 |
|---|---|---|
| 起点事件 | 事件名、当事人、原文、首次、公告、原视频 | 原始链接、主体、发生与发布时间、原始内容；区分本轮最早检出与已确认首发 |
| 时间线 | 时间线、回应、声明、删除、澄清、后续 | 节点、平台、发生／披露／回应／更正时间、引用或前后关系 |
| 观点分歧 | 支持、反对、质疑、辟谣、争议、评论 | 观点原话、理由、指向对象、所引材料、相反表达；不强行归为固定阵营 |
| 情绪变化 | 愤怒、同情、焦虑、嘲讽、疲劳、抵制、冷却 | 情绪对象、阶段、触发事件、原话；不以单帖代表整体风向 |
| 传播节点 | 热搜、热榜、转发、搬运、二创、话题 | 账号或媒体、平台、原帖与转载关系、可见互动及观察时间、榜单记录时间 |
| 事实争议 | 真相、核实、原图、完整版、数据来源、更正 | 各版本原文、数字或身份主张、出处、时间、缺失上下文；保留争议待核查 |
| 利益相关方 | 声明、客服、公告、处罚、下架、整改 | 当事人／平台／监管／企业／用户、回应对象、动作、状态、时间、原文 |
| 实际后果 | 退款、退货、投诉、下架、处罚、销量、客流 | 事件、对象、数量及口径、时间、来源；区分承诺、执行与结果 |
| 跨平台差异 | 事件名与各平台的话题称呼、评论、回应 | 平台、查询与排序、样本范围、观点原话、可见互动及观察时间 |
| 沉降与复燃 | 后续、复燃、周年、再回应、二次传播 | 新触发事件、时间、传播范围、与原事件关系；低检出量不等于热度下降 |

同时寻找原始材料、相反说法、删除或更正记录和完整上下文。当前热榜不能还原历史热度；热榜、互动量、转载数、搜索量和评论样本分别记录，不合并成统一舆情指数。上述方向供内部选词，不把整张清单复述进任务包。

## 4. 给平台分配具体任务

按 [渠道说明](channels.md) 选择本次可用且与问题相关的最小组合。通用搜索用于发现公开网页，媒体用于报道，社区用于用户表达；热榜用于热度观察，不能冒充关键词搜索或用户需求样本。

每项任务明确：一个待查问题、可直接输入的查询、目标平台、材料类型、需带回字段、样本上限及时间边界。同一材料服务多个问题时合并采集并标注用途，不重复执行同一查询。

- 需要用户观点时，分别指定原帖与评论；写明顶层条数、是否需要回复、排序和上下文要求，不默认整页或全量评论。
- 公众号按需带回文章、显示账号、时间及原文地址；候选账号发现不等于主体已核实或取得账号历史。
- 图文和视频区分页面文字、图片内容、字幕与转写；未取得的部分保留缺口。
- 平台不可用时保留失败原因，说明替代渠道覆盖的是原任务哪一部分；通用网页结果不能冒充站内讨论或原帖正文。

## 5. 默认交付简短任务包

本参考用于指导内部搜索设计，不是交付文档的逐节提纲。默认只输出“一小段研究范围＋一张查询任务表＋必要提醒”；简单任务用几句话即可。用户要求采集时，将计划简要写入本轮报告后继续执行；用户只要计划时，到任务包为止。

- 研究范围合并说明问题、视角、对象、地域、具体时间窗和总量上限；别名、扩展与排除只列影响本轮检索的内容，不展开完整对象池。
- 表格保留可直接输入的查询、平台与材料类型、任务所需的额外字段和条数上限。共同时间、地域和基础字段集中说明一次，不逐行重复；相反方向直接纳入相关查询。
- 提醒只写会改变本次执行或结果理解的限制，例如身份难确认、正文缺失或评论上限。通用去重、日期核对、失败处理、停止规则和完整字段定义在执行时遵守，不逐段复述。

用户要求解释、审计或任务确有特殊限制时，再展开相应部分。默认不附 Skill 读取命令、内部路径或设计过程；即使需要审计，也将记录与核心任务表分开。简短不省略用户约束、必要查询或关键返回字段。

```text
研究范围：问题与视角；对象及必要排除；地域／时间窗；总量上限。
共同返回：链接、主体、发布时间、正文状态等基础字段按第 6 节执行；表中仅列本题额外字段。

任务／待查问题｜具体查询｜平台与材料类型｜额外字段｜条数上限

必要提醒：（仅在本题需要时填写）
```

示例：用户要“最近 30 天 AI 编程工具的使用与弃用反馈”，先限定具体工具或说明品类范围，然后按可用渠道选择任务。下列查询分别执行，不将斜线或多行当成搜索语法：

| 待查问题 | 查询示例 | 平台与材料 | 需带回字段 |
|---|---|---|---|
| 在哪些任务中使用 | `[工具名] 工作流` | 小红书原帖 | 任务、使用过程、页面文字状态、时间、链接 |
| 为什么不续费或弃用 | `[工具名] 不续费`；另查 `[工具名] 弃用` | 知乎回答 | 付费或弃用原话、原因、替代方式、时间、链接 |
| 遇到哪些具体限制 | `[工具英文名] bug`；另查 `[工具英文名] limitation` | GitHub Issue | 问题、版本、环境、状态、时间、链接；不据此推断所有用户体验 |

共同范围写明 30 天的具体起止日期，表中补齐各任务候选上限；只有单项边界不同时才另写日期。平台不支持时间筛选时逐条核对，日期缺失标“时间未确认”。

## 6. 返回字段与停止条件

基础字段：`查询／任务标识、平台、链接、标题或原文标识、主体、发布时间、采集时间、对象层、材料类型、正文状态、必要内容或摘要、可见互动字段、覆盖范围与失败原因`。只有原文实际存在的指标才带回；缺失标 `—`，不在采集阶段推算或补造。

先确认主问题、相关对象和相反方向是否已有材料，再决定是否补搜。达到用户上限、材料已满足本轮问题、继续搜索主要重复或渠道受限时停止，明确未覆盖内容；不把“零结果”写成“没有相关现象”。

搜索计划不规定证据等级，不把少量帖子当总体比例，也不把互动量、热榜、转发、搜索量混成一个指数。采集与保存遵守 [语料规范](corpus.md)；需要正式事实审核或研究分析时，再交给用户指定的审核流程，不要求安装某个外部 Skill。
