# 交付物规范

## 执行节奏

- 默认一次完成：采集 → 为推荐篇目获取正文 → 产出报告。
- 用户明确要求先看方向时，才在首轮报告后暂停，再按指示补充平台、条数、关键词或语料。

大范围或高成本任务可先交付小样，但要在开始前说明阶段和验收点。

## 输出目录

**输出位置优先级：**

1. **用户指定了目录** → 放在用户指定的位置
2. **用户没指定且项目有命名规范** → 遵守项目规则
3. **都没有** → 在**当前工作目录**下新建 `<年月日>-信息搜索-<主题>/`

下列文件名是无其他规范时的示例。项目或用户要求 `日期_研究主题_文件名称_CO.扩展名` 时，报告、清单、正文均按该规范命名并更新内部链接。

主题取用户话题的核心词，控制在 10 个字以内，不含空格和标点。
例：`20260809-信息搜索-AI编程工具/`

```
<年月日>-信息搜索-<主题>/
├── 00_采集报告.md   ← 主交付物
├── 01_清单.md       ← 全部候选条目索引
├── 正文/            ← 许可范围内的正文或必要摘录，一条一个 markdown
└── _raw/            ← 接口原始返回，供排查用，不读入上下文
```

日期和主题已在文件夹名中，**内部不再按话题或月份分层**。

## 一、00_采集报告.md

```markdown
# <话题> · 采集报告

> 采集日期：
> 研究问题：<一句话说明本轮要回答什么>
> 证据边界：<必填，写法见下>

## 一、基础信息
- 采集主题、时间、实际使用的检索关键词（全部列出）
- 候选条数表：| 平台 | 条数 | 是否有正文 |
- 各渠道失败情况：哪条渠道、什么错误、改走了哪条降级路径
- 渠道状态表：平台、后端/版本、核验时间、工具/桥接/登录/内容状态、目标或关键词、成功条数、正文状态、错误与降级。未执行的验证写“未验证”，不粘贴含本机细节的完整诊断输出。

## 二、总结分析
### 总结论
（第一段直接给出最主要的结论并加粗，随后展开论证。不单设「一句话结论」章节）
### 二级结论（3–5 条，可按平台、按主题或按差异分类）

## 三、最推荐的 5–8 篇
每篇包含：标题 · 链接 · 互动数据（点赞/收藏/评论）· 内容摘要 · 判断

## 四、全文目录
| 标题 | 平台 | 链接 | 互动数据 |

## 五、后续采样建议
```

### 证据边界：必填项

放开分析之后的主要风险是**把定性样本当作定量结论**——例如用 20 条帖子推导出
「某比例的用户选择了某方案」这类不成立的数据。

按以下标准撰写：

> 本文件是公开讨论的定性样本，不代表总体比例或人均统计。
> 小红书样本来自公开检索结果；知乎样本主要来自可被搜索引擎索引的公开内容，
> 不能代表全部回答或评论。

**必须说明三件事**：样本的性质、能支持什么结论、不能用于什么推断。
帖子作者自述的数字不可相加当作平均值。
营销性质的内容可以说明「用户关注点集中在哪里」，
但其自称的成功率、价格、效果不可作为事实引用。

### 第三节的摘要和判断要写充分

默认推荐 5–8 篇。凡是声称读过全文的条目必须已实际读取正文，不可用检索结果的摘要代替；读取不等于可以复制或再分发全文。
摘要中要包含具体的人物、具体做法和具体数字。
判断部分要说明这篇材料能支持什么、不能支持什么。

正文无法获取的条目若被列入推荐，必须注明「仅基于标题、摘要或互动数据」，不能把平台能力写死为永久状态。

## 二、取几条正文

**筛选顺序不可颠倒：**

1. **先判断相关性。** 根据标题判断与话题是否相关，**由模型判断，不按分数排序**。
   记录本次排序方式。当前 OpenCLI Reddit 搜索默认 relevance，可用 --sort 切换；互动字段 score 不是相关度分数，其他来源也按实际参数说明。

2. **再按互动数排序，且只在同一平台内部比较。**
   不同平台的互动量级差异可达数个数量级，跨平台比较没有意义。

3. **确定条数**：默认 5 条；
   第 3 条之后互动数降至第 1 条的十分之一以下时取 3 条；
   第 5 条之后仍有同量级条目时取 7 条。

默认记录评论数量。只有研究问题需要用户观点、争议或使用反馈时才抽取少量评论正文，并在证据边界中说明筛选方法。

### 各平台的正文获取能力

| 类型 | 平台 | 获取方式 |
|---|---|---|
| 检索结果可能带正文 | Reddit（`selftext`）、Bluesky（`record.text`） | 逐条检查非空、类型和截断；空字段或外链帖不自动标成全文，按需另读详情 |
| 需单独调用 | 公众号（附带脚本 `search` 后 `read`，见 `wechat.md`）、知乎（`download` / `answer-detail`）、Hacker News（`read <id>`） | 次数取决于分页、链接解析、详情和当前接口；串行小批处理，记录实际次数 |
| 需按当前工具验证 | 小红书、B站及其他浏览器平台 | 查看当前帮助并做最小只读测试；失败时标明本轮仅有标题或互动数据 |

**字段获取不到时写「—」，不要推测填充，不要用摘要代替正文。**

## 三、正文文件格式

文件名 `<平台>_<标题前 20 字>.md`，标题中的 `/ \ : * ? " < > |` 替换为下划线。

```markdown
---
标题：
平台：
作者：
发布时间：
点赞：
评论数：
原文链接：
采集时间：
采集工具：
正文状态：全文 / 摘录 / 部分或截断 / 仅元数据
内容来源：帖子 / 评论 / 人工字幕 / 自动字幕 / 机器转写 / 其他
覆盖范围：返回条数、分页是否完成、截断及评论深度；不适用填 —
使用边界：来源许可、用户授权或合理引用说明
---

（来源明确允许、内容属于开放许可或用户有权使用时可保存全文；否则只保存完成研究所需的短摘录、摘要、元数据和原链接。摘录保持原意并与模型总结分开。）
```

字段获取不到时写「—」。**互动数据只要能获取就必须记录**，
后续做热度对比时需要，事后无法补录。

公开页面可访问不等于允许全文再分发。报告和公开仓库不得附带第三方受版权保护的全文语料；本地项目中的保存范围也应服从来源条款和用户权限。

## 四、01_清单.md

```markdown
| 平台 | 标题 | 作者 | 发布时间 | 互动数据 | 采集工具 | 正文状态 | 覆盖范围 | 链接 |
```

**链接必须可以直接打开原帖。** 公众号是例外：搜狗跳转链接超过 400 字符会破坏表格排版，
表中改写定位标识（例如 `opencli-weixin-1.yaml #3` 表示该文件中 rank=3 那条），
脱敏后的必要完整链接保留在本轮 `_raw/` 中。小红书 xsec_token 是定位内容所需的资源签名，应与账号认证令牌区分：仅在本轮本地复核材料保留必要原始链接，不放入公开发布包；对外给出可定位原帖的链接或条目标识，不伪造签名。

**从 YAML 提取字段必须使用 `yaml.safe_load`。** 建议以二进制方式打开文件，让解析器识别 UTF-8 BOM 或 UTF-16；不要仅凭扩展名假设编码。
opencli 将长 URL 存储为折叠标量（`url: >-` 后换行缩进），
用正则 `url:\s*(\S+)` 只能匹配到 `>-` 本身，会导致整列链接失效。

## 五、写入时机

**每条渠道执行完先脱敏，再立即写入 `_raw/`，不要累积到最后统一写。**

渠道失败时保留脱敏错误及退出码、HTTP 状态（可得时）、目标标识、时间、返回条数和后端，报告第一节写摘要。

落盘前剔除 API Key、Authorization、Cookie、账号认证令牌、密码，以及 URL 中的凭证和无关私人字段，不以“原始响应”或“复核”为由保留机密。stdout 与 stderr 分开处理，保留字段名称、类型和定位依据并标注已脱敏；仅保存必要字段时标为“字段摘录”，不声称是未经处理的完整原始响应。

默认关闭 trace；确需排错时先检查捕获范围，使用最小范围的临时诊断，审查、脱敏后才保留。不把可能含登录状态、页面数据或机密的完整 trace 打包进交付物。

**零结果不等于该平台没有相关内容，只表示这个接口本次没有返回。**
报告中必须区分这两种情况，否则后续复盘会产生误判。

在任务和许可范围内保留可复核的候选索引，不因低互动量直接删除相关材料；不因此保留凭证、无关私人内容或无权复制的全文。

## 六、公众号字段与账号发现

- 搜索 JSON 的 `summary` 只作摘要；只有 `read` 的 `article.content` 取得非空目标正文，才能标记已读取。正文与标题、账号和原链接仍须人工或模型核对。
- `publish_time=null`、`date_status` 缺失状态原样保留，日期不明条目不计入“已确认在时间窗内”。不从其他条目或抓取日期补发文日期。
- 保留 `query`、`fetched_at`、`backend` 和 `source_family=sogou_weixin`。附带脚本和 OpenCLI 的搜狗结果可按原文 URL 合并，但保留各查询和定位依据，不把它们作为独立交叉验证；标题相同不是同一文章的充分条件。
- 可选 `accounts` 只是按显示名称汇总的候选公众号，保留 `identity_unverified` 及命中文章；不写成已核实主体、账号排名或完整历史列表。
- `partial/blocked/error` 写入采集报告并保留具体错误码；脚本已经返回的 JSON 是抽取字段，不称作未经处理的完整网页。继续遵守上文脱敏和内容使用范围。

## 七、评论与视频验收

- 评论记录顶层与子回复数量、排序、层级、长度上限和分页情况；小红书保留直接回复关系，Reddit 不把有限深度或长度的评论称为完整讨论。
- 字幕或转写记录视频 URL、语言、时间段与生成方式，有时间戳时保留；可整理行间重复但不改原意。人工字幕、自动字幕、机器转写、模型摘要分开。
- 非空文本仍要核对目标身份和类型；标题、推荐卡片、错误页面不通过正文验收。仅获取部分内容时用“部分或截断”，读到全文但仅获准保存摘录时用“摘录”。
