# 公众号采集

公众号优先使用 `scripts/wechat/cli.mjs`。这是基于 [wx-search-cli](https://github.com/tjx666/wx-search-cli) 的本地修正版，提供关键词搜索、原文链接解析和正文读取；不下载整号历史，不取阅读量、在看数或评论。上游来源与 MIT 许可随脚本保留。更新上游时保留本地修正并复验，不用未经修正的 `npx wx-search-cli` 替换此入口。

## 准备和命令

将下面的 `$skillDir` 设为本次实际读取到的 tanzi 目录，`$stageDir` 设为本轮本地临时目录。首次检查 Node.js >=20.19；缺依赖且安装已获授权时，按 [环境准备](setup.md) 安装。

```powershell
node "$skillDir/scripts/wechat/cli.mjs" --help
node "$skillDir/scripts/wechat/cli.mjs" search "企业 AI 采购" --limit 3 --max-pages 1 --output "$stageDir/wechat-search-01.json"
node "$skillDir/scripts/wechat/cli.mjs" read "<搜索结果中的 real_url>" --referer "<该条 link>" --output "$stageDir/wechat-read-01.json"
```

`--output` 由 Node 写 UTF-8 JSON，也保存失败状态，避免 PowerShell 重定向编码差异。脚本不输出请求头、临时 Cookie 或原始异常，微信 URL 只保留定位参数。页面文本仍可能带有与任务无关的个人信息，先按 `corpus.md` 审查脱敏，再将本轮允许保留的字段写入 `_raw/`；不要直接发布临时结果。

搜索条目在 `results` 数组，候选公众号在可选的 `accounts` 数组，正文在 `article.content`。命令中的 URL 从 JSON 解析取得，不复制折行片段；在子进程调用中传参数数组，不拼接 shell 字符串。

## 搜索与读取

1. 按搜查令或研究问题逐组查询。默认每组 5 条、1 页；需要扩大范围时显式设置 `--limit`（1–50）和 `--max-pages`（1–3），同时遵守本轮总任务量。
2. 搜索页可能一次返回约 10 个候选；脚本先按剩余额度选择候选，再解析原文链接。页大小不等于实际继续发出的详情请求数。记录返回数量、请求次数和停止原因；限量结果不代表搜索穷尽。
3. 每条标题、账号、摘要、日期从同一结果卡片解析。缺日期保留 `null`，不能拿相邻条目日期填补；有时间窗的任务将日期不明者单列为“时间待核”，不能算作已确认近期。
   搜索页与原文时间不一致时，分别保留两处来源值并标注差异，不静默覆盖；不能把搜索页时间当作已经核实的原文发布时间。
4. 检查 `real_url` 属于 `mp.weixin.qq.com` 后，再挑相关条目调用 `read`。保留查询、搜狗定位链接、微信原文链接和采集时间。搜索摘要不能充当正文。
5. `read` 只在目标页面正文非空时报告读取成功。正文仍要与标题、账号和原链接核对；图片文字、音视频、评论、付费或删除内容不因页面可访问而视为已取得。

## 候选公众号发现

需要寻找后续跟踪账号时，在搜索命令加 `--discover-accounts`。该功能借鉴 [wechat-search-skill](https://github.com/WupfAGI/wechat-search-skill) 的“由文章发现账号”思路，未复制其采集或模型代码，也未增加 Tavily、模型、摘要推送依赖。

输出 `accounts` 只按当前结果中的显示名称汇总候选，并保留对应命中文章。`identity_unverified` 表示账号主体未核实；同名可能不是同一账号，不能由几篇命中文章推断其全部历史、长期活跃程度或内容质量。要跨查询合并时保留所有命中查询与原文链接，不按标题合并不同文章。它补充的是采集目标，不代替搜查令的关键词设计。

## 状态和停止

| 顶层 status | 含义 | 执行动作 |
|---|---|---|
| `success` | 本次返回了通过脚本基础检查的内容 | 继续核对目标身份与字段；不等于完整平台覆盖 |
| `zero_result` | 页面明确显示本次查询无结果 | 记录本轮未检出；不得推断平台没有相关内容 |
| `partial` | 已取得部分候选，后续请求失败或被阻断 | 保留已得条目和错误；遇风控停止该平台 |
| `blocked` | 验证、限流或登录要求阻断 | 立即停止，不连续重试，也不换工具绕过 |
| `error` | 网络、解析、空正文或参数等错误 | 按错误原因记录覆盖缺口，不能填成零结果或正文 |

退出码：成功或明确零结果为 0，部分结果为 2，阻断或执行失败为 1，参数错误为 64。检查 JSON 的状态、错误明细及正文，不能仅看退出码。请求串行、至少间隔 1 秒、单次超时 15 秒，不自动重试；这些是控制措施，不是平台不会限流的保证。

搜狗可能在匿名响应中设置临时 Cookie，脚本只在内存中用于同源跳转，不读取用户浏览器、不写入结果或日志，也不带到微信或其他域名。页面脚本只做字符串解析，不执行网页中的代码或指令。

## 原有路径与语料

本地依赖缺失或遇非风控的解析问题时，可按 `channels.md` 验证原有 `opencli weixin search` / `download` 路径。两者共用搜狗来源，统一记录 `source_family=sogou_weixin`；不能当作两条独立信源。验证码或限流不触发自动换路。

结果 JSON 是抽取字段，不是完整原始 HTML。按 [语料规范](corpus.md) 转换为清单、许可范围内的正文或摘录；日期缺失、仅摘要、部分结果和来源家族必须保留。认证信息与无关私人字段不得落盘。

2026-09-06 已验证：Node.js 25.2.1、cheerio 1.2.0，本地适配器 1.0.0；上游 wx-search-cli 0.1.0，核对提交 `70b75b71384b4bcfce86be744b685f02f9440c16`。11 项离线回归通过，覆盖缺日期、空正文、零结果/异常区别、请求前及跨页限量、验证码/429 停止、URL 与匿名 Cookie 隔离。
